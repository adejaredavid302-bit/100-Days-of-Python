# Day 16 – Coffee Machine (Object-Oriented Programming)

## Overview

On Day 16, I rebuilt the Coffee Machine project using **Object-Oriented Programming (OOP)** instead of procedural programming. Rather than writing all the logic myself, I learned how to use pre-written classes and objects to build the application.

## Project Description

This project simulates a coffee machine that allows users to:

- Select a drink (Espresso, Latte, or Cappuccino)
- View the machine's resource report
- Process customer payments
- Check ingredient availability
- Prepare the selected drink
- Turn the machine off.

## Topics Covered

- Object-Oriented Programming (OOP)
- Classes and Objects
- Attributes and Methods
- Importing Classes
- Creating Objects
- Calling Methods
- Reading Documentation
- Working with Multiple Python Modules

## What I Learned

- The difference between a **class** and an **object**.
- How to create objects from classes.
- How to call methods on objects.
- How different classes communicate to complete a program.
- How to read documentation to understand how pre-written code should be used.
- Why Object-Oriented Programming makes larger applications easier to manage.

## About the Starter Code

For this project, the following classes were **already written and provided** in the course resources:

- `Menu`
- `MenuItem`
- `CoffeeMaker`
- `MoneyMachine`

My responsibility was **not** to write these classes from scratch, but to understand their documentation and use their methods correctly to build the Coffee Machine application. This project focused on learning how to work with existing code, which is an essential skill in real-world software development.

## Challenges

- Understanding Object-Oriented Programming for the first time.
- Learning how different objects interact with one another.
- Understanding methods that return objects and values.
- Reading documentation instead of writing every function myself.

## Reflection

Day 16 was one of the most challenging projects so far because it introduced a completely different programming style. Although it took time to understand how the different classes worked together, completing this project gave me a much stronger understanding of Object-Oriented Programming and how developers use existing libraries and modules in real-world applications.
